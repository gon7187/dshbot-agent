# Готовые решения памяти и графа для DSHBOT

Дата: 2026-10-23. Метод: только чтение (GitHub API, `npm view`, исходники и README через веб). Ничего не устанавливалось и не запускалось. Числа звёзд, релизов и дат снимались 2026-10-23 и быстро устаревают.

## 1. Критерии (из задачи)

1. Локально, без обязательного облака и внешнего сервиса. LLM для извлечения — только DeepSeek через OpenAI-совместимый API, эмбеддинги локальные или никаких.
2. Без тяжёлой инфраструктуры (Neo4j, Postgres, Qdrant как обязательные). Идеал — SQLite или файлы, в крайнем случае встраиваемая БД.
3. Встраивается в Node/TS: npm-пакет, MCP по stdio или небольшой сайдкар.
4. Лёгкий RSS (весь бот ≤ 250 МБ).
5. MIT/Apache/BSD, телеметрии нет или она выключается.

## 2. Главный вывод

Готового решения, которое одновременно извлекает факты LLM-ом, строит граф и укладывается в критерии 1–4, нет.

- Граф с LLM-извлечением (Graphiti, Cognee) — Python, тянет графовую БД и модели эмбеддингов: проваливает критерии 2, 3, 4.
- Лёгкие TS-решения (mem0 OSS, MemOS-плагин) графа знаний не дают: mem0 вырезал graph memory из OSS в v3, MemOS строит цепочку «след → политика → навык», а не граф сущностей.
- Практичный путь: граф без отдельного конвейера извлечения. Факты и связи пишет сама модель (DeepSeek) через инструменты в фоновом ревью опыта (DESIGN §8.1, как Hermes). Это убирает требование «LLM для извлечения» к библиотеке памяти.

## 4. Кандидаты

### 4.1 MCP `server-memory` (основной)

- Что даёт: граф из сущностей (`name`, `entityType`), наблюдений (строки) и связей (`from`, `to`, `relationType`). Инструменты: `create_entities`, `create_relations`, `add_observations`, удаления, `read_graph`, `search_nodes`, `open_nodes`.
- Чего нет: извлечения фактов (пишет вызывающая модель), векторов, времени, забывания, дедупа сверх «имя уникально».
- Стек: TS, зависимости `@modelcontextprotocol/server` ^2.3.1 и `zod`. Хранение — `memory.jsonl`, путь через `MEMORY_FILE_PATH`. Есть блокировка файла и миграция со старого `memory.json`.
- Поиск: подстрока без учёта регистра по имени, типу и наблюдениям (`searchNodes`, `index.ts:656`). Вес, ранжирования нет. Для сотен сущностей хватает, для тысяч слабо.
- Подключение: stdio-сайдкар (`npx @modelcontextprotocol/server-memory` или бинарь `mcp-server-memory`). Либо читать и писать JSONL напрямую, формат тривиален.
- Эмбеддинги: не нужны.
- Телеметрия: в `index.ts` нет сетевых вызовов (поиск по `fetch`, `http`).
- Лицензия: корневой LICENSE описывает переход MIT → Apache-2.0, в `package.json` поле `"SEE LICENSE IN LICENSE"`. Для личного бота допустимо, но это не чистый SPDX.
- Активность: коммиты почти ежедневно (2026-10-13, 10-18, 10-19), релиз 2.0.0 опубликован в npm 2026-10-19.
- Оговорка: `engines.node >= 24` (у нас 26 на этой машине, DESIGN говорит >= 22). Для сайдкара это предупреждение npm, но на проде надо держать Node 24+.
- RSS: не измерен. Ожидание — десятки МБ на процесс (Node + MCP SDK), граф целиком в памяти и перезаписывается файлом при каждой мутации.

### 4.2 `@beledarian/mcp-local-memory` (запасной)

- Что даёт: память (свободный текст) плюс сущности, связи, наблюдения, задачи; гибридный поиск FTS5 + `sqlite-vec` (MiniLM локально) или только FTS5; поиск по периодам («last week», ISO-даты); важность с затуханием; пометки «устарело», «неверно», восстановление, экспорт, забывание.
- Извлечение: стратегия `ARCHIVIST_STRATEGY=nlp` (compromise, chrono-node), без LLM. Опциональные LLM-функции ходят только на настроенный `OLLAMA_URL`. DeepSeek напрямую не подключить (формат Ollama, не OpenAI), поэтому извлечение остаётся за агентом.
- Стек: TS, `better-sqlite3`, `sqlite-vec`, `@huggingface/transformers` 4.2 (ONNX), `compromise`. Нужны нативные сборки. Node >= 22.
- Эмбеддинги: первая семантическая выборка скачивает модель с Hugging Face (исходящий запрос, данные не уходят). Без них остаётся FTS5.
- Подключение: stdio, также SSE с токеном.
- Телеметрия: не найдена (`fetch` только в Ollama-клиентах и тестах).
- Активность: создан 2026-02, push 2026-09-14, 60 звёзд, один автор. Главный риск — поддержка.
- RSS: с эмбеддингами заметно выше (onnxruntime + модель), без них скромный. Не измерен.

### 4.3 mem0 OSS (TS-пакет `mem0ai`)

- Что даёт: извлечение фактов одним вызовом LLM (в v3 только ADD, без UPDATE/DELETE), гибридный поиск (семантика + BM25 + совпадение сущностей), история в SQLite.
- DeepSeek: есть готовый провайдер `llms/deepseek.ts` (baseURL `https://api.deepseek.com`).
- Графа в OSS нет: «Graph memory moved to Platform» (`docs/migration/oss-v2-to-v3.mdx`). Это закрывает тему графа.
- Эмбеддинги обязательны: векторное хранилище — основа. Локально: `fastembed` (ONNX, нативный), Ollama, HF-сервер. Встроенное хранилище векторов — SQLite (`better-sqlite3`, peer-зависимость).
- Телеметрия: PostHog, включена по умолчанию, выключается `MEM0_TELEMETRY=false` (`utils/telemetry.ts`).
- Проблема модели: ADD-only копит противоречия («живёт в Москве» и «переехал в Казань» рядом), а §7 требует архивацию и правку с сохранением версии.
- Вердикт: годится как «автоматический журнал фактов», но не как граф. Не берём.

### 4.4 Graphiti (Zep)

- Что даёт: темпоральный граф знаний (факты с интервалами валидности, инвалидация противоречий), извлечение сущностей и фактов LLM-ом, гибридный поиск. Самое близкое по смыслу к «граф связей между фактами, людьми, проектами».
- Стек: Python >= 3.10, обязательные `neo4j`, `openai`, `posthog`. Встраиваемые драйверы: Kuzu (помечен deprecated, сам Kuzu архивирован 2025-10-10) и falkordblite (embedded Redis-сервер, Python >= 3.12). Готовый MCP-сервер поставляется с FalkorDB в Docker.
- Эмбеддер обязателен (по умолчанию OpenAI); локальный вариант — `sentence-transformers` (тянет torch).
- Телеметрия: PostHog, выключается `GRAPHITI_TELEMETRY_ENABLED=false`.
- Вердикт: качество лучшее, цена — Python-сайдкар с графовой БД и моделью эмбеддингов, сотни МБ. Критерии 2, 3, 4 не проходят. Возвращаться, только если простой граф окажется недостаточным.

### 4.5 Cognee

- Что даёт: конвейер «add → cognify → search», граф и векторы, онтологии. Умолчания — SQLite + LanceDB + файловая граф-БД; с версии 1.0 всё можно держать на одном Postgres.
- Стек: Python 3.10–3.14, тянет `litellm`, `instructor`, `lancedb`, `fastapi`, `sqlalchemy`, `tokenizers`, `huggingface-hub`, `rdflib` и т. д. Без ключа LLM извлекает граф локальной моделью GLiNER и эмбеддит локальной моделью (скачиваются при первом запуске).
- Телеметрия: включена, `TELEMETRY_DISABLED=1`.
- Вердикт: слишком тяжёлый для бота ≤ 250 МБ, только Python. Нет.

### 4.6 Letta (MemGPT)

- Репозиторий `letta-ai/letta` теперь указывает на `letta-code` (TS-харнесс с терминальным UI, App Server и каналами), старый Python-сервер выведен в ветку `archive`. Это конкурирующий агентный рантайм, а не библиотека памяти.
- Анонимная телеметрия описана в `PRIVACY.md`, отключается в конфиге.
- Вердикт: не подходит, дублирует наш харнесс.

### 4.7 basic-memory

- Идея близка к нашей: markdown-заметки как источник истины, SQLite-индекс, граф из wiki-ссылок, MCP.
- Лицензия AGPL-3.0 — не проходит К5. К тому же Python >= 3.12 и платный облачный план в README.
- Вердикт: нет. Идею «markdown первичен, индекс производный» оставляем в нашем `knowledge/`.

### 4.8 MemOS (`@memtensor/memos-local-plugin`)

- Что даёт: слои L1 (следы шагов), L2 (политики), L3 (модель мира), навыки; трёхуровневый поиск; гибрид FTS5 + вектор; дедуп; есть веб-вьюер на 127.0.0.1:18801. Явно заявлена поддержка DeepSeek Harness (адаптер Cordis) и `provider: host` для LLM, то есть вызовы идут через активного провайдера DSH (DeepSeek).
- Хранение: `data/memos.db` (SQLite, `better-sqlite3`). Эмбеддинги: `local` (`Xenova/all-MiniLM-L6-v2` через transformers.js) или OpenAI-совместимый API.
- Телеметрия: включена по умолчанию, агрегаты и выбранные провайдеры раз в сутки, выключается `telemetry.enabled: false`. Пакет содержит `telemetry.credentials.json`; куда уходит, не проверялось.
- Несовместимость версий: peer-зависимости DSH `>=0.1.0-rc.5 <0.2.0`, у нас `0.2.1-rc.3`. README адаптера прямо говорит, что DSH — developer preview и поздние версии «may require adapter changes».
- Содержательно: это замена не §7 (факты), а §8 (обучение, навыки, политики). Конфликтует с нашими правилами (замороженный снимок, декларативные записи, провенанс) — у плагина свой цикл записи и свой инъекционный блок `<memos_context>` на каждый ход.
- Вердикт: не берём для памяти; можно изучить для §8.1 как референс. RSS с transformers.js и вьюером вероятно выше бюджета.

### 4.9 LightRAG и nano-graphrag

- LightRAG: RAG по документам с графом сущностей. Умолчание — файлы (JSON KV, `nano-vectordb`, `networkx`), без внешних БД, MIT, активен (push 2026-10-22). Python, зависимости pandas, google-genai, tiktoken; эмбеддинги обязательны; индексация дорогая по числу LLM-вызовов; для диалоговой памяти (мелкие, часто обновляемые факты, забывание) не предназначен. REST-сервер есть, Node-клиента нет.
- nano-graphrag: последний релиз 0.0.8 в 2024-10, фактически заморожен.
- Вердикт: нет.

### 4.10 graphify

- Что это: превращает папку (код, документы, PDF, изображения, видео) в `graph.json` + `GRAPH_REPORT.md` + `graph.html`. Код — tree-sitter без LLM; документы — LLM. Эмбеддингов нет, это обход графа.
- Для памяти агента не подходит: нет API записи фактов, обновление — пересборка корпуса (`--update`), отслеживание версий и забывание не предусмотрены, нет диалоговой модели. Рядом продаётся облачный продукт Graphify Cloud.
- Телеметрию поиском по репо не нашёл, но полного аудита не делал.
- Годится на другом: индексировать `memory/knowledge/` и документацию DSHBOT как read-only карту для вопросов «где лежит X». Как слой памяти бота не использовать.

### 4.11 LongMemory (бывший OpenMemory, `CaviraOSS`)

- Что даёт: двухвременная память (valid time и recorded time), консервативное объединение сущностей, граф рёбер, режимы recall (strict, historical, associative), провенанс, SQLite. Один TS-движок: npm, CLI, HTTP, MCP. Извлечение без LLM (детерминированные правила), эмбеддинги по умолчанию синтетические (хеширование), опционально OpenAI/Ollama/Gemini/локальный HTTP.
- Телеметрия: по коду `LONGMEMORY_TELEMETRY` — локальные метрики запросов в процессе; наружу не проверялось.
- Минусы: огромный набор жёстких зависимостей в `package.json` (aws-sdk, googleapis, ffmpeg, pg, ioredis, notion, octokit, pdf-parse) — вес установки и RSS неизвестны; проект переименован, ему год, большая часть заявлений (бенчмарки, «cognitive engine») не проверена независимо; нативный `sqlite3`.
- Вердикт: по функциям ближе всех к «временной памяти с графом на SQLite в Node», но риск по весу и зрелости высок. Ставить в пилот только после замера RSS и ревью зависимостей.

### 4.12 Остальное, быстро

- Zep: `getzep/zep` теперь репозиторий примеров к облачному Zep Cloud. Self-hosted Zep отсутствует; из семейства остаётся Graphiti (4.4).
- `doobidoo/mcp-memory-service`: Python, REST, OAuth, дашборд, причинный граф. Активен, Apache-2.0, но это отдельный сервис, не сайдкар на ≤ 250 МБ.
- memvid: Rust-ядро, один файл `.mv2`, Node SDK с большим набором зависимостей (langchain, llamaindex, ocr, exceljs). Графа знаний нет. Не изучал глубже.
- supermemory: локальный бинарь `supermemory-server` v0.0.x (HTTP API на :6767), встроенный графовый движок. Исходники сервера в репозитории не обнаружены (образы prebuilt), URL-ингест идёт через облачный reader. Критерий прозрачности не проходит.
- Hermes-плагины (Honcho, Hindsight, Supermemory, Mem0, Holographic) в каталоге Hermes — не оценивались.

## 5. Рекомендация

### Основной: MCP `@modelcontextprotocol/server-memory` 2.0 как слой «связи»

Почему:
- единственный кандидат, который проходит все пять критериев без оговорок по инфраструктуре: TS, файл, нет эмбеддингов, нет сети;
- граф из коробки (люди, проекты, факты как наблюдения, связи с типом);
- поддерживается организацией MCP, живой репозиторий;
- не требует отдельного LLM-конвейера: извлечением занимается DeepSeek через вызовы инструментов в фоновом ревью (§8.1).

Ограничения, с которыми согласиться заранее: нет времени и версий (противоречия модель снимает сама, удаляя старое наблюдение и добавляя новое), поиск по подстроке, граф целиком в памяти. Для личного бота (порядка сотен сущностей) приемлемо.

### Запасной: `@beledarian/mcp-local-memory`

Берём, если подстрочного поиска и отсутствия времени окажется мало: даёт FTS5, поиск по периодам, затухание важности, пометки устаревших записей, при желании локальные векторы. Платим нативными модулями, одним автором и неизмеренным RSS при включённых эмбеддингах. Без эмбеддингов (`nlp`) хорош и скромен.

### Не сейчас

Graphiti — единственная «настоящая» темпоральная графовая память с LLM-извлечением. Когда и если простого графа не хватит, поднимать как отдельный Python-сайдкар на falkordblite, с отключённой телеметрией и локальными эмбеддингами, и отдельным решением по бюджету RSS. Для первой версии это перебор.

## 6. Как ложится на DESIGN §7

Из `packages/memory` ничего не заменяется: все слои §7 остаются.

| Слой §7 | Решение |
|---|---|
| identity, USER.md, MEMORY.md, scratchpad | остаются нашими: размеры, снимок на сессию, ревизия |
| knowledge/*.md | остаётся: проза с YAML-summary; граф ссылается на файлы по имени |
| journal, история, `createRecallIndex` (FTS5) | остаются: диалоговый поиск и «рецепт» recall |
| **новое: связи** | MCP `server-memory`: люди, проекты, факты как наблюдения, отношения |

Правила, чтобы граф не нарушил §7:

- В префикс и в замороженный снимок граф не попадает (иначе ломается кэш). Только по запросу: инструмент `search_nodes` / `open_nodes`, как `recall`.
- Писать в граф может только фоновое ревью опыта и инструмент `memory` через белый список (§8.1); обёртка отклоняет императивы и негативные утверждения об инструментах (правила Hermes) и пишет провенанс: источник и время хранятся в наблюдении текстом, например `[tg:owner 2026-10-23] …`. Записи из недоверенных источников не продвигаются.
- Архивация вместо удаления: перед `delete_observations` обёртка копирует старое наблюдение в `journal/`.
- Бэкап файла `memory.jsonl` вместе с остальной памятью; путь задаётся `MEMORY_FILE_PATH` внутри `memory/`.
- Сайдкар — отдельный stdio-процесс. Его RSS не входит в процесс бота, но входит в общий бюджет хоста. Если MCP-клиента в ядре ещё нет (DESIGN §11.6 переносит MCP на потом), граф можно читать и писать напрямую в JSONL тонкой обёрткой на 100–150 строк без зависимостей, а совместимость формата сохранит возможность подключить сам сервер позже.

Перед установкой любого пакета из этого списка — проверка по `install-risk-review` (правило из глобальных инструкций).

## 7. Не проверено

- RSS и время старта ни одного кандидата не измерялись (ничего не запускалось); все оценки по составу зависимостей.
- Телеметрия проверена поиском по репозиториям (`gh search code`) и чтением файлов телеметрии, а не полным аудитом. Для basic-memory, doobidoo, memvid, supermemory и LongMemory (внешние вызовы) — не проверена.
- MCP `server-memory`: размер транзитивных зависимостей `@modelcontextprotocol/server` 2.x, поведение при росте графа, потеря данных при падении во время перезаписи JSONL (в коде есть блокировка и атомарная запись, тестов не запускал).
- Лицензия `server-memory` — смешанная MIT/Apache с отметкой «SEE LICENSE»; юридически не разбиралась.
- MemOS: реальная совместимость плагина с DSH 0.2.1-rc.3, адрес, куда шлёт телеметрия (`telemetry.credentials.json`), RSS с transformers.js, какой вариант конфигурации у DSH-адаптера. Версия плагина в репо (2.0.16-beta.1) и в npm (2.0.20) различаются.
- mem0: фактический RSS с `fastembed`, наличие других сетевых обращений кроме PostHog и уведомлений (`notices.ts`).
- Graphiti и Cognee: реальное потребление памяти с falkordblite / LanceDB, качество извлечения моделью DeepSeek (структурный вывод у DeepSeek слабее, чем у OpenAI; это известный риск Graphiti на не-OpenAI моделях, здесь не тестировался).
- Cognee: какая граф-БД стоит по умолчанию сейчас (Kuzu или его форк).
- Kuzu архивирован (2025-10-10); форки (например, Ladybug) не оценивались.
- Letta-code: API памяти и отсутствие телеметрии в нём не изучались.
- Hermes-каталог плагинов (Honcho, Hindsight, Holographic), Memori (лицензия NOASSERTION), SuperLocalMemory, `MematiBas42/mcp-memory-graph` (PolyForm Noncommercial, не проходит К5), `r14c/mcp-server-memory-sqlite` (0 звёзд, Node >= 24.2, только форк официального сервера на SQLite) — просмотрены поверхностно или не оценивались.
- Все бенчмарки (LoCoMo, LongMemEval) — заявления вендоров, не воспроизводились.
- Звёзды монорепозиториев (`modelcontextprotocol/servers`, MemOS, mem0) относятся ко всему репозиторию, а не к конкретному пакету памяти.
