# Переменные окружения

[English version](en/CONFIG.md)

Код читает переменные из окружения процесса. В установке службы они лежат в
`~/.config/dshbot/dshbot.env`, который systemd подключает через
`EnvironmentFile`; файл создаётся установщиком с правами `600`. Пустые значения
обычно считаются незаданными, исключения отмечены в таблицах. Полный список
команд владельца — в [COMMANDS.md](COMMANDS.md), установка — в
[INSTALL.md](INSTALL.md).

## Подключение, пути и время

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота Telegram от [@BotFather](https://t.me/BotFather); без него демон не стартует. | обязательна |
| `DEEPSEEK_API_KEY` | Ключ API DeepSeek; без него демон не стартует. | обязательна |
| `DEEPSEEK_BASE_URL` | Базовый адрес Messages API DeepSeek. | `https://api.deepseek.com/anthropic` |
| `TELEGRAM_API_ROOT` | Базовый адрес Bot API Telegram; нужен для локального зеркала или прокси. | `https://api.telegram.org` |
| `DSHBOT_HOME` | Каталог данных: `state.db`, память, сессии, workspace и кэши бота. | обязательна в службе; установщик задаёт `~/.local/share/dshbot` |
| `DSHBOT_ISOLATION` | Режим запуска демона: `container` (bwrap с фейковым root) или `host` (напрямую). | `host` |
| `DSHBOT_TZ` | Часовой пояс владельца в формате IANA, например `Europe/Moscow`; задаёт расписания, тихие часы и вечерний итог. | часовой пояс хоста |
| `DSHBOT_SHA` | Короткий sha запущенного кода для `/status`; нужен, когда каталог приложения не git-репозиторий. | HEAD текущего checkout, затем `stable` из `adopt.json` |
| `DSHBOT_DOCTOR_GRACE_MS` | Окно ожидания доктора восстановления в миллисекундах: при неактивном юните доктор столько ждёт его возвращения в `active` и только потом сообщает владельцу о падении. Пустое, нечисловое, нулевое или отрицательное значение даёт значение по умолчанию. | `30000` |
| `HOME` | Домашний каталог владельца: путь `~/.config/dshbot`, миграция и профиль команд хоста. | домашний каталог пользователя |
| `PATH` | Поиск исполняемых файлов, Chromium и инструментов песочницы. | PATH процесса-демона без каталогов mise shims |

## Характер владельца

Личный стиль владельца не хранится в репозитории: его файл лежит в
`DSHBOT_HOME/persona/`. Гости не получают ни личный файл владельца, ни
нейтральный `persona/character.md` репозитория.

| Файл | Назначение | По умолчанию |
| --- | --- | --- |
| `DSHBOT_HOME/persona/character.md` | Личный характер владельца: непустой файл добавляется после нейтрального `persona/character.md` репозитория в системном промпте владельца и не заменяет его. Пустой или отсутствующий файл оставляет характер репозитория. | `persona/character.md` репозитория |

Файл читается при запуске демона. После изменения характера перезапустите бота.

## Провайдеры моделей

Кроме DeepSeek по `DEEPSEEK_API_KEY` раннер умеет ходить к провайдерам
харнесса `dsh-llm-pi-ai`: `zai` (z.ai Coding Plan по ключу), `openai-codex`
(вход ChatGPT по OAuth), `openai`, `anthropic`, `google`, `xai`, `moonshotai`,
`kimi-coding`, `minimax`, `openrouter`, `github-copilot` и `qwen-token-plan`.
Вход по ключу или OAuth сохраняется в файл учётных данных харнесса
`DSHBOT_HOME/dsh/.credentials.yaml` с правами `0600`; ключ DeepSeek в него не
записывается. Файл лежит вне workspace, и инструменты агента (`read`, `list`,
`grep`, `exec`) его не читают.

В каталоге моделей (`runner.models()`, меню «Модели» завода и меню ролей)
показываются только провайдеры с сохранённым входом. Удаление записи входа
убирает модели этого провайдера из каталога; маршрут `deepseek-official`
работает от `DEEPSEEK_API_KEY` и в файле учётных данных не нуждается.

Уровни рассуждения модель объявляет сама через адаптер
(`resolveModelInfo`): у DeepSeek это `off`, `low`, `high` и `max`, у моделей
провайдеров — их собственный набор (`minimal`, `medium`, `xhigh` и т. п.).
`/effort` и экран роли показывают уровни текущей модели; сохранённый уровень,
которого модель не предлагает, не отправляется, и ход идёт на уровне модели по
умолчанию.

Постоянные тулзы владельца: каталог `DSHBOT_HOME/tools` создаётся при старте и
монтируется в песочницу `exec` владельца (ходы и задачи по расписанию) на запись;
запись в остальной `DSHBOT_HOME` (кроме workspace) по-прежнему закрыта, `HOME` — пустой tmpfs.
Туда направлены `uv tool` (`UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`), `pip --user` (`PYTHONUSERBASE`), `npm -g`
(`NPM_CONFIG_PREFIX`), `cargo install` (`CARGO_INSTALL_ROOT`, `CARGO_HOME`) и `go install` (`GOBIN`), а их кэши
(`UV_CACHE_DIR`, `PIP_CACHE_DIR`, `npm_config_cache`, `GOMODCACHE`, `GOCACHE`) лежат в `tools/cache`. Каталоги программ
(`tools/bin`, `tools/python/bin`, `tools/npm/bin`, `tools/cargo/bin`, `tools/go/bin`) стоят в `PATH` песочницы сразу
после каталога node демона. Установка идёт без подтверждения владельца; каждая команда, добавившая программы, оставляет
в журнале демона строку с их именами. Гостевой `exec` каталог не видит. Каталоги `tools` не добавляются в `PATH` и окружение `host_exec` и демона, а `bwrap`
и `/usr/bin/env` запускаются по исходному `PATH` демона или по абсолютному пути, поэтому установленная тулза не
подменит программы демона. Общее окружение Python: если `tools/pyenv` — готовый venv (есть `bin/python3` и `bin/pip`, реальный путь внутри `tools`), то на каждой команде `exec` владельца `tools/pyenv/bin` стоит в `PATH` раньше всех каталогов, а `VIRTUAL_ENV` указывает на `tools/pyenv`, так что `python3`, `pip` и `uv pip install` работают с ним. Демон окружение сам не создаёт и не меняет: его заводит установщик (`scripts/install.sh`) или владелец командой `python3 -m venv <DSHBOT_HOME>/tools/pyenv` (путь абсолютный: `exec` работает в `workspace`); подхватывается оно без перезапуска демона. Если `tools/pyenv` нет или это не venv, команды выполняются как раньше. Резервная копия `DSHBOT_HOME` каталог `tools` не включает. Системные пакеты (apt) не ставятся: в песочнице нет root.

### Хосты `host_exec`

Каждая команда локального `host_exec`, включая чтение и проверку личности машины, требует согласия владельца: карточки или ранее выданного разрешения на этот точный алиас хоста и команду. Команды, запрещённые guard, не запускаются. Для SSH прежняя политика guard и подтверждений сохраняется; `exec` в ограниченной песочнице работает по своей прежней политике.

Алиасы хостов живут в `DSHBOT_HOME/hosts.json`: имя → `ssh`-цель (пользователь и адрес) либо локальный алиас этой машины. Имя алиаса — метка, а не описание машины: `pc` может вести на десктоп владельца, а не на хост, где живёт бот, и команда выполнится у него.

Поэтому первая команда на незнакомом алиасе — проверка личности, а не догадка: `hostname; cat /etc/machine-id`, сверить с машиной, где работает бот, и только потом трогать файлы, службы и ключи. Смешение хостов замечается не сразу: имена пользователей и каталоги выглядят похоже, а лишний `sudo` на чужой машине — уже выход за пределы задачи.

`pkill -f <шаблон>` через ssh убивает и собственную команду, если шаблон встречается в её строке запуска: оболочка получает сигнал первой, и вызов возвращается с кодом 255 без вывода. Убивать по `pid` из `pgrep -f`, а не по подстроке.

## OpenAI-совместимый API для голосовых клиентов

Эндпоинт `POST /v1/chat/completions` принимает запросы голосовых и других
OpenAI-совместимых клиентов и отдаёт задачу ходу модели владельца. Xiaozhi —
один из примеров такого клиента; подключение и пример блока `LLM` описаны в
разделе [OpenAI-совместимый API](INSTALL.md#openai-совместимый-api).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `DSHBOT_OPENAI_PORT` | TCP-порт OpenAI-совместимого эндпоинта `/v1/chat/completions` для голосовой колонки; без него вместе с токеном эндпоинт выключен. | не задана (эндпоинт выключен) |
| `DSHBOT_OPENAI_TOKEN` | Bearer-токен OpenAI-совместимого эндпоинта: заголовок `Authorization: Bearer <токен>`; без него вместе с портом эндпоинт выключен. | не задана (эндпоинт выключен) |
| `DSHBOT_OPENAI_HOST` | Адрес прослушивания OpenAI-совместимого эндпоинта. | `127.0.0.1` |
| `DSHBOT_OPENAI_TLS_CERT` | Путь к PEM-сертификату HTTPS-эндпоинта; задаётся вместе с ключом. | не задана (без пары с ключом используется HTTP) |
| `DSHBOT_OPENAI_TLS_KEY` | Путь к PEM-ключу сертификата HTTPS-эндпоинта; задаётся вместе с сертификатом. | не задана (без пары с сертификатом используется HTTP) |

## Лаунчер и установщик

Эти переменные читают `scripts/install.sh` и `scripts/dshbot-run.sh`, а не
демон. Подробности установки — в [INSTALL.md](INSTALL.md).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `DSHBOT_CONTAINER_RO` | Дополнительные пути владельца для MCP и браузера, смонтированные в контейнер только для чтения; список через двоеточие. | пусто (только тулчейн и системные каталоги) |

## Наследуемое окружение команд

Эти переменные бот не настраивает сам: он передаёт их дочерним командам
`host_exec` и `exec`, если они заданы у процесса. Секреты демона в такое
окружение не попадают.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `LANG` | Локаль дочерних команд. | `C.UTF-8` |
| `LC_ALL` | Приоритетная локаль дочерних команд. | не задана |
| `LC_CTYPE` | Классификация символов для дочерних команд. | не задана |
| `USER` | Имя пользователя в окружении `host_exec`. | не задана |
| `LOGNAME` | Имя пользователя для утилит входа в окружении `host_exec`. | не задана |
| `SHELL` | Оболочка дочерних команд. | `/bin/bash` в песочнице |
| `TMPDIR` | Временный каталог дочерних команд. | `/tmp` в песочнице |
| `TERM` | Тип терминала дочерних команд. | `dumb` в песочнице |
| `TZ` | Часовой пояс дочерних команд. | часовой пояс хоста |
| `PAGER` | Пейджер дочерних команд. | `cat` в песочнице |
| `GIT_PAGER` | Пейджер git в дочерних командах. | `cat` в песочнице |
| `NO_COLOR` | Отключает цветной вывод дочерних команд. | `1` в песочнице |
| `FORCE_COLOR` | Включает цветной вывод дочерних команд. | не задана |
| `SSH_AUTH_SOCK` | Сокет ssh-agent для команд хоста. | не задана |
| `SSH_AGENT_PID` | PID ssh-agent для команд хоста. | не задана |
| `XDG_CONFIG_HOME` | Каталог конфигурации XDG для команд хоста. | `~/.config` |
| `XDG_DATA_HOME` | Каталог данных XDG для команд хоста. | `~/.local/share` |
| `XDG_CACHE_HOME` | Каталог кэша XDG для команд хоста. | `~/.cache` |
| `XDG_RUNTIME_DIR` | Каталог runtime XDG для команд хоста. | не задана |
